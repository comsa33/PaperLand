# PaperLand 제품 아이디어 브리프

## 핵심 컨셉

PaperLand는 논문 검색기가 아니라 **연구 지형도와 공백 후보 탐지기**다.

사용자가 특정 연구 분야나 키워드를 입력하면, 관련 논문들이 의미적으로 가까운 위치에 배치된 지도로 나타난다. 논문이 많이 쌓인 곳은 이미 점유된 영토처럼 보이고, 주변 맥락은 풍부하지만 직접 연구가 적은 곳은 공백 후보로 강조된다.

> 목표: "이 분야에 어떤 논문이 있나?"를 넘어서, "어디까지 연구됐고, 어디가 아직 덜 탐색됐나?"를 보여준다.

## 사용자 문제

- 새로운 연구 주제를 찾을 때 기존 논문 목록만으로는 분야 전체의 포화도를 파악하기 어렵다.
- 논문 검색 서비스는 이미 아는 키워드를 더 잘 찾게 해주지만, 아직 이름 붙지 않은 조합이나 빈틈은 잘 보여주지 않는다.
- 연구자는 보통 "이 아이디어 이미 누가 했나?", "이 조합은 빈 영역인가?", "요즘 뜨는 곳은 어디인가?"를 동시에 알고 싶어 한다.
- 리뷰 논문을 읽기 전에도 빠르게 지형을 훑어볼 수 있는 탐색 도구가 있으면 주제 선정 시간이 줄어든다.

## 제품 포지셔닝

| 기존 도구 | 주된 사용 방식 | PaperLand의 차이 |
|-----------|----------------|------------------|
| Google Scholar | 키워드 기반 검색 | 지도 기반으로 포화 영역과 저밀도 영역을 함께 탐색 |
| Semantic Scholar | 논문 검색, 인용, 추천 | 공백 후보와 연구 질문 후보를 별도 인터랙션으로 제공 |
| Connected Papers | 특정 논문 주변 네트워크 | 한 논문이 아니라 분야 전체의 지형과 시간 변화를 표시 |
| 리뷰 논문 | 사람이 정리한 분야 개관 | 최신 데이터 기반으로 빠르게 초안 지형을 생성 |

## 핵심 은유

- **논문**: 지도 위의 점 또는 작은 토지 단위
- **클러스터**: 비슷한 연구들이 모인 영토
- **밀집 지역**: 이미 많은 연구가 진행된 포화 영역
- **최근 확장 지역**: 새 논문이 빠르게 늘어나는 성장 영역
- **저밀도 경계**: 서로 다른 분야가 맞닿지만 논문 수가 적은 융합 후보
- **고립 고영향 논문**: 인용은 많지만 후속 연구가 적은 확장 후보

중요한 표현 원칙: 앱은 "여기는 아무도 안 했다"라고 단정하지 않는다. 대신 **공백 후보**, **저밀도 영역**, **탐색 가치 높은 영역**처럼 근거 기반의 조심스러운 표현을 사용한다.

## MVP 기능

### 1. 키워드 기반 지도 생성

사용자가 연구 키워드, arXiv 카테고리, 또는 seed paper를 입력한다.

예시:
- `retrieval augmented generation medical QA`
- `LLM hallucination detection`
- `multi-agent reinforcement learning`
- `self-corrective RAG evaluation`

앱은 관련 논문을 수집하고 제목, 초록, 연도, 인용수, venue, 저자 정보를 바탕으로 지도를 만든다.

### 2. 논문 영토 지도

메인 화면은 2D 임베딩 지도다.

- 논문은 의미적 유사도에 따라 배치된다.
- 클러스터는 옅은 영역 또는 격자 셀로 묶인다.
- 논문 수가 많은 곳은 더 진하게 보인다.
- 최근 논문이 많은 곳은 별도 레이어로 강조된다.
- 사용자는 줌인하면 개별 논문을, 줌아웃하면 토픽 영역을 본다.

### 3. 공백 후보 하이라이트

지도 위에서 다음 유형의 영역을 후보로 표시한다.

| 후보 유형 | 설명 | 예시 해석 |
|-----------|------|-----------|
| 클러스터 사이 저밀도 영역 | 두 연구 흐름 사이에 직접 연결 논문이 적음 | "RAG 평가"와 "법률 도메인" 사이 조합 부족 |
| 주변 고밀도 중심부의 빈 공간 | 인접 주제는 많은데 특정 조합이 적음 | "의료 QA"는 많지만 "self-correction 평가"는 부족 |
| 고영향 고립 논문 주변 | 인용 많은 논문은 있으나 후속 연구가 적음 | 확장 실험이나 재현 연구 후보 |
| 시간상 정체 영역 | 과거 연구는 많지만 최근 논문이 적음 | 새로운 모델/데이터셋으로 재검증 가치 |
| 방법-도메인 불균형 | 방법 논문은 많지만 특정 응용 분야 검증이 적음 | 방법론의 도메인 이전성 연구 후보 |

### 4. 영역 클릭 분석 패널

공백 후보나 클러스터를 클릭하면 오른쪽 패널에 다음 정보를 보여준다.

- 영역 요약 라벨
- 대표 키워드
- 대표 논문 3-5개
- 논문 수, 최근 3년 증가율, 평균 인용수
- 왜 공백 후보로 판단했는지
- 인접 클러스터
- 가능한 연구 질문 후보
- 관련 검색 쿼리 추천

예시 문구:

> 이 영역은 "RAG evaluation", "legal QA", "self-correction" 클러스터 사이에 위치하지만 직접적으로 세 키워드를 모두 연결하는 논문 밀도는 낮습니다. 인접 논문들은 주로 일반 QA나 의료 도메인에 집중되어 있어, 법률 도메인에서의 self-corrective RAG 평가가 탐색 후보일 수 있습니다.

### 5. 시간 슬라이더

연도별로 지도가 어떻게 점유되는지 볼 수 있다.

- 특정 연도까지의 누적 논문 표시
- 최근 1년, 3년, 5년 기준 성장 영역 표시
- 새롭게 생긴 클러스터 강조
- 과거에는 빈 영역이었지만 최근 점유된 영역 표시

## 추천 점수 설계

공백 후보를 단순히 논문 수가 적은 곳으로만 판단하면 품질이 낮아질 수 있다. 주변 맥락과 연구 가능성을 함께 봐야 한다.

### Whitespace Score

공백 후보 점수는 다음 요소를 조합한다.

| 요소 | 의미 |
|------|------|
| Local Density | 해당 영역 안의 논문 밀도 |
| Neighbor Density | 주변 영역의 논문 밀도 |
| Topic Bridge Potential | 서로 다른 클러스터를 연결할 가능성 |
| Citation Gravity | 주변 대표 논문들의 영향력 |
| Recency Gap | 최근 논문이 상대적으로 적은 정도 |
| Query Match | 사용자의 관심 키워드와의 관련도 |

초기 MVP에서는 정교한 수식보다 설명 가능한 휴리스틱이 좋다.

예:

```text
Whitespace Score =
  high_neighbor_density
  + cluster_boundary_score
  + citation_gravity
  - local_density
  - recent_saturation
```

## UX 원칙

### 단정 대신 근거

좋지 않은 표현:
- "이 주제는 아무도 연구하지 않았습니다."
- "여기가 미개척지입니다."

좋은 표현:
- "현재 수집된 데이터 기준으로 직접 연결 논문이 적습니다."
- "인접 분야 대비 저밀도 영역입니다."
- "추가 문헌 검토가 필요한 공백 후보입니다."

### 연구자의 다음 행동까지 연결

각 공백 후보는 단순 표시로 끝나면 안 된다. 반드시 다음 행동을 제공한다.

- 관련 논문 읽기 목록
- 추가 검색 쿼리
- 가능한 연구 질문
- 필요한 검증 방법
- 주의해야 할 기존 연구

### 지도는 설명 가능해야 한다

임베딩 지도는 축이 직관적이지 않을 수 있다. 그래서 사용자가 "왜 이 점들이 가까운가?"를 알 수 있게 해야 한다.

- 공통 키워드
- 공통 citation neighborhood
- 유사 abstract 문장
- 같은 데이터셋/태스크/방법론

```text
+--------------------------------------------+-------------------+

+----------------------------------------------------------------+
```

## 사용자 시나리오

### 시나리오 1: 대학원생의 연구 주제 탐색

1. 사용자가 `LLM hallucination detection`을 검색한다.
2. 지도에서 factuality evaluation, retrieval verification, uncertainty estimation, medical QA 등의 영토가 보인다.
3. 사용자는 "medical QA + uncertainty + retrieval verification" 사이의 공백 후보를 클릭한다.
4. 앱은 대표 논문, 왜 저밀도인지, 가능한 연구 질문을 보여준다.
5. 사용자는 후보를 북마크하고 관련 논문 리스트를 export한다.

### 시나리오 2: 지도 위에 내 아이디어 올려보기

1. 사용자가 자신의 abstract 초안을 입력한다.
2. 앱은 해당 초안을 임베딩해서 지도 위에 핀으로 표시한다.
3. 주변 논문들과의 거리, 가장 가까운 기존 연구, 차별화 후보를 보여준다.
4. 너무 붐비는 영역이면 "차별화가 필요한 축"을 제안한다.

### 시나리오 3: 교수/PI의 분야 트렌드 확인

1. 사용자가 특정 분야와 최근 5년 필터를 선택한다.
2. 성장 속도가 빠른 영역과 정체된 영역이 색상으로 나뉜다.
3. 앱은 emerging cluster 목록과 대표 논문을 요약한다.
4. 랩의 다음 프로젝트 후보를 비교할 수 있다.

## 데이터 파이프라인 초안

1. 논문 수집
   - arXiv, Semantic Scholar, OpenAlex, Crossref 중 선택
   - MVP는 arXiv + Semantic Scholar 조합이 현실적

2. 전처리
   - 제목, 초록, 카테고리, 연도, 저자, venue, citation count 정규화
   - 중복 논문 병합

3. 임베딩
   - 제목 + 초록 기반 embedding
   - 사용자의 seed abstract도 같은 공간에 매핑

4. 2D 투영
   - UMAP 기반 좌표 생성
   - 대용량일 경우 사전 계산 후 캐시

5. 클러스터링과 라벨링
   - HDBSCAN 또는 BERTopic
   - 클러스터 대표 키워드와 대표 논문 추출

6. 공백 후보 탐지
   - 격자 또는 hex cell 단위 밀도 계산
   - 주변 밀도 대비 중심 밀도가 낮은 영역 탐지
   - 클러스터 경계와 인용 영향력 반영

7. 설명 생성
   - 각 클러스터와 공백 후보에 대해 LLM으로 요약 생성
   - 반드시 근거 논문과 수치가 함께 표시되도록 구성

## MVP 범위 제안

### 꼭 필요한 것

- 키워드 입력
- 논문 리스트 수집 또는 샘플 데이터 로딩
- 2D 논문 지도
- 클러스터 라벨
- 논문 밀도 레이어
- 공백 후보 5-10개 표시
- 후보 클릭 시 근거와 연구 질문 표시

### 나중에 해도 되는 것

- 실시간 대규모 크롤링
- 계정/팀 협업
- 완전 자동 novelty 판정
- 복잡한 3D 지형
- 리뷰 논문 자동 생성
- 논문 PDF 본문 분석

## 리스크와 방어 전략

| 리스크 | 문제 | 방어 전략 |
|--------|------|-----------|
| 공백 오판 | 실제로는 논문이 있는데 데이터에 없을 수 있음 | "수집 데이터 기준" 명시, 원문 검색 쿼리 제공 |
| 지도 해석 오류 | 임베딩 좌표가 절대적 의미를 갖는다고 오해 | 근접 이유와 대표 키워드 표시 |
| 최신성 부족 | 최근 논문 반영이 늦을 수 있음 | 데이터 갱신 시점 표시 |
| 논문 품질 혼합 | 낮은 품질 논문도 같은 점으로 표시 | citation, venue, recency 필터 제공 |
| 너무 많은 정보 | 초보자가 압도될 수 있음 | 기본 모드는 단순하게, 고급 레이어는 토글 |

## 성공 지표

- 사용자가 한 세션에서 공백 후보를 북마크하는 비율
- 지도에서 영역 클릭 후 논문 리스트를 여는 비율
- seed abstract 입력 후 주변 논문 비교를 완료하는 비율
- 추천 연구 질문을 export하는 비율
- 사용자가 "이 주제는 이미 포화인가?" 질문에 답을 얻는 데 걸리는 시간

## 장기 비전

PaperLand가 충분히 발전하면 분야별 "연구 영토 변화"를 지속적으로 관찰하는 도구가 될 수 있다.

- 분야별 주간/월간 지도 업데이트
- 새로 점유된 영역 알림
- 내 관심 분야 주변의 신규 논문 알림
- 연구 아이디어와 기존 논문 간 유사도 추적
- 랩/팀 단위 연구 포트폴리오 지도
- 논문 작성 전 novelty sanity check

## 다음 결정 사항

1. 첫 MVP의 데이터 소스를 arXiv only로 할지, Semantic Scholar/OpenAlex까지 붙일지 결정한다.
2. 첫 화면을 "키워드 검색" 중심으로 할지, "샘플 분야 지도" 중심으로 할지 결정한다.
3. 지도 렌더링을 deck.gl, D3 canvas, 또는 WebGL 직접 구현 중 무엇으로 시작할지 결정한다.
4. 공백 후보 점수를 휴리스틱으로 먼저 구현할지, 클러스터 기반 분석을 먼저 구현할지 결정한다.
5. 데모용 대표 분야를 하나 고른다. 예: RAG, LLM hallucination, AI agents, medical QA.
